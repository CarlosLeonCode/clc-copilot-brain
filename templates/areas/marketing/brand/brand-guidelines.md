# Brand Identity & Voice Guidelines

## 1. Brand Essence & Personality
Our brand voice is **authoritative, pragmatic, developer-native, and transparent**. We talk to builders, architects, and engineering leaders.

### Tone Principles:
- **Pragmatic over Promotional**: Avoid hyperbole ("revolutionary", "magic", "game-changer"). Use precise claims ("deterministic", "schema-validated", "zero lock-in").
- **Concise over Wordy**: Lead with the outcome, back it with architectural evidence, end with concrete action.
- **Respect the Reader's Intelligence**: Never talk down to the user or obscure technical trade-offs.

---

## 2. Banned Words & Replacements

| Do Not Use | Preferred Replacement |
| :--- | :--- |
| "Revolutionary AI platform" | "Open source second brain engine" |
| "Effortless 10x synergy" | "Measurable reduction in onboarding ramp" |
| "All-in-one magical suite" | "Composable, version-controlled knowledge architecture" |
| "Disruptive paradigm" | "Deterministic git-based workflows" |

---

## 3. Formatting & Code Presentation Standards
- Code blocks must always specify language tags (`bash`, `json`, `typescript`, `markdown`).
- File paths should use relative markdown links.
- Emphasize key takeaways using standard GitHub alerts (`[!NOTE]`, `[!TIP]`, `[!WARNING]`).
